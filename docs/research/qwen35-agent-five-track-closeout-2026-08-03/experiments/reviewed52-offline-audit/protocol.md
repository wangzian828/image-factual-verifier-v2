# H7 protocol: reviewed-52 full offline hint and Decision audit

Status: locked before execution.

## Question

Across all frozen reviewed-52 snapshots, what source-hint and post-Decision
quality problems remain outside the nine strictly qualified replay cases?

## Frozen inputs

- the existing reviewed-52 runtime snapshots;
- the manifest generated by `scripts/build_reviewed52_replay_manifest.py`;
- an optional frozen replay batch summary for consumption/fallback linkage.

The audit must not retrieve new sources, freely search, or call an LLM/VLM.

## Candidate classifications

Every candidate Evidence row receives deterministic primary status and flags for:

- no concrete visible property;
- overlong or multi-property hint;
- hint with weak subject/Claim lexical binding;
- hint potentially irrelevant to the current Claim;
- already reviewed by a prior Decision;
- relation scope/stance/directness/quality not qualified;
- strictly qualified;
- replay unavailable;
- resolved pixel Evidence not consumed or explicitly irrelevant;
- deterministic fallback or engineering failure.

Heuristic relevance/subject flags are triage signals, not semantic verdicts.
The JSON report must retain the original Evidence ID, snapshot, Claim, source
text, hint, and all reasons so every flag is manually auditable.

## Metrics and outputs

- exact counts for cases, snapshots, candidates, and each status/flag;
- per-case and per-Evidence rows in JSON;
- a concise Markdown report with distributions and highest-risk examples;
- consistency checks against manifest totals and replay summaries;
- non-zero exit on malformed input or broken invariants.

## Acceptance

All 976 frozen candidate Evidence rows are classified exactly once, report
totals reconcile with the source manifest, and no engineering gap is hidden by
the nine-case replay aggregate.
