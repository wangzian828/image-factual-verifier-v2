# Benchmark 构建方案

---

## 一、任务定义

**Image Credibility Assessment**：给定单张图片（图内可能含嵌入文字，如字幕条、标题栏、水印），判断该图片传达的信息是否可信。

任务的本质是**语义层面的真实性判断**，而非像素级伪造检测。判断依据可以是视觉推理、外部事实核查、逻辑分析等，取决于图片本身的造假方式。与现有工作的区别：

| 任务 | 输入 | 关注层面 |
|------|------|----------|
| 伪造图像检测（FaceForensics++等） | 图片 | 像素/频域篡改痕迹 |
| 图文一致性检测（NewsCLIPpings等） | 图文对 | 图文配对是否正确 |
| 文本事实核查 | 文本 | 文字声称是否属实 |
| **本任务** | **单张图片** | **图片传达的信息是否可信** |

输出：`real` / `fake` / `unverifiable`

---

## 二、数据集样本标注维度

每张样本的完整标注结构如下：

```json
{
  "verdict": "real / fake / unverifiable",
  "fake_type": "EF1 / AF2 / CD3 / ...",
  "context_description": {
    "subject": ["图内主要人物/机构"],
    "location": ["地点线索"],
    "event": ["事件语境"],
    "attribute": ["关键可见属性，如数字、标识、旗帜"],
    "relation": ["主体间关系/行为"],
    "time": ["时间线索"],
    "text_in_image": ["OCR提取文字"],
    "uncertainty": ["不确定项"]
  },
  "manipulated_slot": "被改动的槽位名（fake样本填写）",
  "key_contradiction": "假在哪一点，正确事实是什么（fake样本填写）",
  "evidence_requirement": "internal / external / provenance"
}
```

**字段说明：**

| 字段 | 适用样本 | 用途 |
|------|---------|------|
| `verdict` | 全部 | 最终判定 |
| `fake_type` | fake | 造假类型，见第三节 |
| `context_description` | 全部 | 图像语义槽位，监督agent信息抽取；构建时作为造假模板 |
| `manipulated_slot` | fake | 被改动的槽位，监督agent错误定位 |
| `key_contradiction` | fake | 具体错误点，监督agent推理解释 |
| `evidence_requirement` | 全部 | `internal`=图内可解；`external`=需外部检索；`provenance`=需来源溯源 |

## 三、Fake 数据的四层分类体系

### 顶层一：Existence Fabrication（存在性捏造）
图片声称某事/某关系存在，但实际不存在或从未发生。

| 子类 | 定义 | 核查手段 | 示例 |
|------|------|----------|------|
| **EF1** 主体行为捏造 | 真实人物/机构被捏造了某行为或事件，涵盖主体已故/已离职导致的状态矛盾，以及主体仍活跃但行为无任何外部记录两种情形 | 确认主体当前状态 + 新闻搜索 + 官方渠道核查 | 已故歌手发布新专辑现场照、已卸任总统出席国事活动、某国央行宣布加密货币为法定货币 |
| **EF2** 主体关联捏造 | 图内两个或多个有明确身份的真实主体（人物/机构）被捏造成存在某种具体联系（会面、合作、冲突、隶属等），但该联系从未存在 | 识别图内主体身份 + 搜索两者关联记录 | 两国领导人被捏造成秘密会晤、竞争企业被捏造成宣布合并、从未同台的艺人被捏造成联合演出 |
| **EF3** 事件/现象无依据 | 某重大事件或现象被声称存在，但违背基本科学常识或物理规律，或搜索查无此事 | 常识推理 + 新闻数据库检索 | 月球表面出现液态海洋、大型强子对撞机制造出稳定黑洞、某国际机场因故永久关闭 |
| **EF4** 合成主体捏造 | 图片中的人物/场景由 AI 完全生成，声称是真实存在的人或真实发生的事，但主体本身并不存在 | 人脸反搜无结果 + AI生成痕迹检测 | AI生成的"政要"出席活动照、完全虚构的"事故现场"、不存在的人物被配上真实机构头衔 |

---

### 顶层二：Attribute Forgery（属性伪造）
真实场景/真实对象，但关键属性被篡改。

| 子类 | 定义 | 核查手段 | 示例 |
|------|------|----------|------|
| **AF1** 数字/统计篡改 | 图内量化信息（数字、年限、比分、统计数据）被改 | 与权威来源数值比对 | 奥运会金牌榜第一名得牌数被夸大、某国 GDP 增速截图数字与官方公布不符、球队联赛积分表名次被调换 |
| **AF2** 人物/机构身份错标 | 图内真实人物/标识被归属到错误的人/机构 | 人脸/标识搜索核实真实身份 | 某物理学家照片被配上错误的诺贝尔奖得主头衔、竞争对手产品图被标注成自家品牌 |
| **AF3** 时空属性错误 | 真实建筑/地标的位置、形态或结构与真实不符 | 地图/卫星图比对 + 建筑资料核查 | 大本钟被移植到上海陆家嘴、悉尼歌剧院出现在沙漠中、胡佛大坝被 PS 成已干涸状态 |
| **AF4** 文字/标志替换 | 图内铭文、logo、旗帜、公式等符号信息被替换 | OCR 提取后与原版比对 | 林肯纪念堂铭文被篡改、知名品牌 logo 中的文字被偷换、化学分子式中原子数被改错 |

---

### 顶层三：Context Displacement（语境错置）
图像内容本身可以是真实的，但被放在错误的时空/平台语境中。

| 子类 | 定义 | 核查手段 | 示例 |
|------|------|----------|------|
| **CD1** 时间戳伪造 | 图内时间戳为未来日期或与内容逻辑矛盾的时间 | 读取图内时间戳，判断与内容的合理性 | 社区停水通知日期是三年后、比赛成绩单显示尚未举办的赛事日期、政府公文落款时间早于该机构成立时间 |
| **CD2** 旧图新用 | 真实历史图像被置于新事件语境，图内有可溯源的时代特征 | 反图搜索找原始出处和时间 | 十年前洪灾现场照配"本周暴雨"标题、历史军事演习照被说成近期冲突实拍、老旧工厂设备图被说成最新产线 |
| **CD3** 平台/账号伪造 | 伪造社交媒体或官方机构截图，账号名/认证标识/UI 细节造假 | UI 细节与平台真实版本比对 + 账号历史存档查询 | 伪造某科学家的推文截图声称重大发现、伪造 WHO 官方公告截图发布健康警告、伪造央行公告截图宣布货币政策调整 |
| **CD4** 地理线索错置 | 图内含可核查的地理特征（路牌/语言/建筑风格），但这些特征与声称地点矛盾 | 提取图内地理线索与声称地点交叉比对 | 含阿拉伯语路牌的街景被说成发生在东京、带有东南亚建筑风格的场景被声称是欧洲某国 |

---

### 顶层四：Visual Inconsistency（视觉不一致）
图片制作层面存在视觉物理破绽，无需外部知识、纯靠视觉推理即可发现。子类划分待参考相关文献确定。

| 子类 | 定义 | 核查手段 | 示例 |
|------|------|----------|------|
| **VI1** 视觉物理矛盾 | 图内细节存在视觉物理矛盾，如光影方向、镜面反射、肢体与持物空间关系、透视比例等自相矛盾 | 图内视觉推理 | 人物左手持物但右侧有握持痕迹、镜中反射与实物不对称、阴影方向与光源矛盾 |

## 四、图像生成方案

所有样本（real和fake）均采用AI图像生成，不使用真实图片。

### 生成流程

**Real样本：**
- 以结构化语境描述（`context_description`）作为prompt，生成内容与事实一致的图片
- 图内可包含嵌入文字（字幕条、标题栏、水印等），内容与图像语义一致

**Fake样本：**
- 在real样本的 `context_description` 基础上，改动一个槽位
- 以修改后的槽位描述为prompt，以real样本为参考图，图生图生成对应假图
- 单变量扰动原则：每次只改一个槽位，保证造假类型清晰
- 替换值从语义相似样本库检索，而非随机编造，保证迷惑性

### 槽位与fake_type对应

| 改动槽位 | 对应fake_type |
|---------|--------------|
| subject | EF1、EF4、AF2 |
| relation | EF2 |
| event | EF3 |
| attribute | AF1、AF4 |
| location | AF3、CD4 |
| time + 嵌入文字 | CD1、CD2 |
| platform/source + 嵌入文字 | CD3 |
| 图内视觉细节 | VI系列 |

## 标注流程

### 语境描述来源

`context_description` 是构建图像时的输入prompt，槽位在生成前已确定，不需要生成后再提取。

### 图像质量校验

每张生成图经VLM校验，确认图像内容与prompt槽位一致；不符合的重新生成。

### 标注产物

每条样本完整标注见第二节。fake样本的 `manipulated_slot` 和 `key_contradiction` 由构建流程自动记录，无需人工标注。

## Real 和 Unverifiable 数据

**Real 类**：收集与 fake 场景对应的真实图片，作为负样本。

**Unverifiable 类**：长尾/私人场景，无外部可核查记录；或证据存在但不足以定论的边界案例。约为 fake 类的 1/3。

## Agent训练框架（不行，要重新设计）

### 训练目标

训练一个仅看图的agent，通过模仿强教师的核查轨迹，学会工具调用策略和推理逻辑。

### 教师模型

- **输入**：图 + 全部标签（verdict / fake_type / context_description / manipulated_slot / key_contradiction / evidence_requirement）
- **能力**：强模型（GPT-4o / Claude Opus）+ 完整工具集（OCR / 反图搜索 / 新闻检索 / 实体识别等）
- **输出**：结构化核查轨迹

教师轨迹包含：
```json
{
  "initial_observation": ["图内可见线索"],
  "suspicion_type": "判断可能的造假类型",
  "key_fields_to_verify": ["需核查的关键字段"],
  "tool_sequence": [
    {"tool": "工具名", "target": "查询目标", "result": "返回结果"}
  ],
  "evidence_collected": ["收集到的证据"],
  "evidence_conflicts": ["证据冲突点"],
  "stop_reason": "为何停止搜索",
  "final_verdict": "real / fake / unverifiable",
  "reasoning": "最终推理解释"
}
```

### 学生模型

- **输入**：仅图片
- **能力**：弱模型 + 同样的工具集
- **训练目标**：模仿教师轨迹，学习：
  - 看到哪类图应优先查什么（工具选择策略）
  - 何时双向假设、何时单向推理（推理策略）
  - 哪类证据缺失意味着unverifiable（边界判断）
  - 何时停止搜索（终止策略）

### 监督信号

- **结构化轨迹监督**：工具调用序列、中间假设、证据收集步骤
- **最终结果监督**：verdict + key_contradiction
- **过程质量监督**：工具选择是否与manipulated_slot对齐、推理路径是否高效

### 核心价值

标签不直接告诉学生答案，而是帮教师生成最优轨迹。学生通过模仿轨迹，隐式学到了：
- 从图出发如何规划核查路径
- 不同造假类型对应的核查策略
- 何时该保守判断unverifiable

## 八、评测指标

- **Accuracy**：三分类整体准确率
- **Per-type Accuracy**：按 EF/AF/CD/VI 及各子类分别统计
- **False Alarm Rate**：real 被误判为 fake 的比例（过度怀疑）
- **Abstention Recall**：unverifiable 被正确识别的比例
- **Reasoning Quality**：verdict 对 + key_contradiction 被正确识别的比例（区分"蒙对"和"真懂"）
