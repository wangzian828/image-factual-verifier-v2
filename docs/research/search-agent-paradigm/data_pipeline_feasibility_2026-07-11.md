# 训练数据生成管线与真实评测数据可行性评估

日期：2026-07-11

适用方向：Internet-grounded synthetic visual investigation

说明：以下人日是假设已有可调用 LLM、生图、搜索、浏览和 OCR 接口，并由熟悉项目的研究工程人员执行的粗估，不包含论文写作、模型正式训练和 API 排队时间。

## 1. 结论先行

整体判断：

| 部分 | MVP 难度 | 论文级难度 | 主要瓶颈 |
|---|---:|---:|---|
| 互联网事实锚定的合成图片 | 中等 | 中高 | 单变量干预是否真的成立；自动视觉验收 |
| clean evidence graph | 中高 | 高 | 来源是否独立、证据是否真的支持原子 claim |
| 冻结搜索环境与工具回放 | 中高 | 高 | 网页保存、检索真实性、版本与许可 |
| 轨迹与候选动作数据 | 高 | 很高 | 真实执行多个分支的成本和动作价值归因 |
| 复用公开真实数据做评测 | 中等 | 中等 | 任务语义适配、图片/网页失效 |
| 自建论文级真实评测集 | 高 | 很高 | claim–image–evidence gold、时间冻结、泄漏与版权 |
| hidden live rolling test | 高 | 很高且持续 | 每轮人工核验、环境漂移与不可复现性 |

关键判断：**训练管线规模化的难点不是生成图片，而是生成后验证；真实评测集的难点不是下载图片，而是建立可辩护的 gold。**

推荐策略：先用 50 个互联网 world、每个 4 个视觉变体完成 200-case MVP；评测先复用公开集筛出 100–200 例，再自建 100–150 例高质量隐藏真实测试。不要第一轮就构建数千个真实评测案例。

## 2. 任务边界

训练主体不要求每个合成 query image 都有配对原始照片：

```text
真实互联网网页与事实
→ hidden world/evidence graph
→ 受约束的 synthetic query image
→ Agent 对原始/冻结网页执行搜索
→ 学习搜索驱动的视觉重观察与停止策略
```

它训练：

- 从图中形成候选事实与未知项；
- 搜索真实事实世界；
- 根据网页结果返回检查图像区域；
- 区分支持、反驳和证据不足；
- 分配工具预算并正确停止。

它不直接训练或证明：

- query image 的首发来源；
- 真实转载、裁剪、压缩和平台传播历史；
- live 反向搜图的真实命中分布。

后三项需要真实图片评测轨道。

## 3. 训练数据生成管线难度

### 3.1 推荐管线

```text
事件发现与过滤
→ 网页抓取、冻结与来源去重
→ 原子事实和 evidence graph
→ 选择可视觉化 claim
→ 生成 scene specification
→ 生成基础图
→ 同管线生成支持/单事实反例/证据不足变体
→ 区域级视觉验收与泄漏检查
→ 建立搜索环境
→ blind Agent rollout
→ privileged verifier 标注动作价值
```

### 3.2 分步骤评估

| 步骤 | 难度 | 可自动化程度 | MVP 粗估 | 主要失败方式 |
|---|---:|---:|---:|---|
| 事件候选发现 | 低—中 | 80–95% | 0.05–0.15 人日/world | 事件过于知名、不可视觉化、只有单一来源 |
| 网页抓取与冻结 | 中 | 70–90% | 0.05–0.2 人日/world | 403、动态页面、正文缺失、图片热链、页面更新 |
| 来源族聚类/转载去重 | 中高 | 60–80% | 0.1–0.3 人日/world | 多站实际复制同一上游；发布时间不可靠 |
| 原子事实与 evidence span 抽取 | 中高 | 70–85% 后需复核 | 0.2–0.5 人日/world | 网页只相关但不蕴含；时间限定丢失；冲突被抹平 |
| 选择视觉 claim 与 region plan | 中高 | 50–75% | 0.1–0.3 人日/world | 事实无法从像素恢复；必须靠隐藏 caption 才成立 |
| scene spec 与基础图生成 | 中 | 85–95% | 0.05–0.2 人日/world | 文字错误、空间关系错误、地标变形、时代风格错 |
| 单变量反事实编辑 | 高 | 50–75% | 0.2–0.8 人日/world | 编辑一个槽位时同时改变人物、天气、镜头或背景 |
| insufficient 变体生成 | 中高 | 60–80% | 0.1–0.3 人日/world | 移除目标线索后仍有代理线索；实际变成另一确定标签 |
| 自动/人工视觉验收 | 高 | 40–70% | 0.3–1.0 人日/world | judge 与生成器共偏差；OCR/计数/几何等细节漏检 |
| 搜索索引/冻结环境 | 中高 | 70–90% | 初建 5–15 人日，之后 0.05–0.15/world | 搜索过于干净；gold 页面永远排名第一；不似真实 Web |
| blind rollout 与候选动作分支 | 高 | 60–85% | 0.2–1.0 人日/world | 工具成本高；分支爆炸；教师知道答案造成后见偏差 |
| leakage probes 与 split | 中高 | 70–90% | 初建 3–8 人日 | 生成器、模板、OCR、分辨率或主题泄露标签 |

这里的 `world` 是一个互联网事件/事实图；推荐每个 world 产生 4–8 张图，而不是每张图重复做整套网页标注。

### 3.3 最大技术瓶颈：反事实完整性

目标是：

```text
I_supported 与 I_refuted
仅在目标 fact atom 上不同
```

实际图像生成常出现：

- 改路牌时同时改变建筑和天气；
- 改人数时改变镜头和空间布局；
- 改时间线索时引入新的服饰、光照或车型差异；
- 移除文字后留下颜色、徽标或构图代理线索。

因此需要三层验收：

1. 程序检查：尺寸、hash、OCR、目标区域、元数据和编码流程；
2. 多模型盲审：不提供标签，分别列出图像事实并做 pairwise diff；
3. 人工抽检：重点检查所有 test、低一致性样本和高价值反事实。

任何验收器都不能只问“图片是否符合 prompt”。应分别判断：目标事实是否出现、非目标事实是否保持、是否出现新的决定性线索、图片是否仍可自然调查。

### 3.4 RIS 可检索性验收：从“原图配对”改为“视觉邻域”

合成 query image 不必在互联网中有逐像素原图，但若一个 case 要训练 RIS 驱动的调查，它必须在真实或冻结索引中存在**有用的视觉邻域**。每个 world 可以收集并标注若干网页图片：

```text
同一地点/地标
同一事件的其他视角
同一对象或设施
相似但属于其他时间/事件的困难负例
```

生成后实际调用目标 RIS 后端，把 top-k 保存为 observation，并检查：

- 是否至少出现一个能建立候选或区分候选的视觉邻居；
- 该邻居所在页面是否含有可核验的时间、地点、事件或对象信息；
- Agent 是否必须比较 query 的某个局部区域才能利用结果；
- 是否存在高相似但错误的结果，用于测试 false bridge；
- 无结果是否是搜索后端 data void，而不是被构造者误标为事实反证。

据此把 case 分为：

```text
RIS-actionable      有用视觉邻居，适合训练/评测 RIS 策略
text-search-only    没有稳定视觉邻居，但 OCR/网页搜索可调查
unsearchable        缺少任何可靠检索钩子，应拒收或作为显式 data-void 案例
```

这一步会产生真实的后端依赖；需要记录搜索引擎、日期、地区、query 图版本和 top-k，并在另一个后端或另一日期抽样复测。纯文本生成后未经真实 RIS 检验，不能假设它天然可由相关图搜到。

### 3.5 数据规模与人力估算

#### 技术验证 MVP

```text
50 worlds
× 4 images（支持、反驳、不可判定、困难负例）
= 200 query cases
```

产物至少包括 250–500 个网页、100–200 个来源族、200 张 query 图、区域/事实绑定和约 50–100 条完整 rollout。

粗估：

- 管线工程：15–30 人日；
- world/evidence 审计：15–30 人日；
- 图像生成与验收：10–25 人日；
- rollout 与数据清洗：10–25 人日；
- 合计：约 50–110 人日。

若只做 verdict SFT、不做候选动作分支，可降到约 30–60 人日；若要可靠 RL 过程奖励，会升到约 80–150 人日。

#### 论文级第一版

建议 300–500 worlds、1,500–3,000 query images，而不是一开始追求上万独立 world。成熟管线后的边际人工成本可争取降至 0.5–1.5 人日/world，但长尾反事实仍需人工审计。

粗估：3–6 人团队、2–4 个月；如果要求多语言、完整动作分支和严谨冻结搜索环境，可能达到 4–8 个月。

### 3.6 可显著降难度的范围控制

第一版只选：

- 有至少两个独立公开来源的事件；
- 非人脸身份核验；
- 有稳定、可视觉化、可局部定位的事实；
- 不依赖精确生成长文本；
- 不依赖不可见的作者意图；
- 支持通过地点标识、对象属性、数量、空间关系、公开事件元素进行区分。

暂缓：细粒度人物身份、微小文字、精确新闻现场复原、私人事件、只有社媒单帖的世界，以及必须依赖真实 RIS 才能裁决的案例。

## 4. 真实图片评测集难度

真实评测不应把 RIS 理解为只负责“找回第一张原图”。反向搜图首先是一个**视觉相关证据发现工具**：它可以返回同图转载、裁剪/编辑版本、同一事件不同视角、同一地点或对象在其他时间的图片，以及容易误导 Agent 的视觉相似负例。建议拆成两个评分轨道：

| 轨道 | 需要最早/原始图吗 | 主要评估 |
|---|---:|---|
| Semantic/RIS investigation | 不需要；需要真实传播中的 query image、明确 claim、相关图检索结果和充分外部证据 | 利用相关图片提出候选事件、定位视觉差异、搜索后重观察和证据裁决 |
| Provenance investigation | 需要原始或“最早可确认”来源，并明确无法证明绝对首发时的表述 | 同图溯源、裁剪/编辑链、早期语境和来源不确定性 |

前者可以做成 150–250 例的主真实测试；后者只做 30–80 例高成本子集。这样既能证明主要的主动调查迁移，也不会让“绝对首发图”成为整个 benchmark 的硬前提。

对冻结的 RIS top-k 结果，推荐标注以下关系，而不是只标 `original/not-original`：

```text
R0 exact_duplicate             完全相同或重编码
R1 derived_version             裁剪、加字、镜像、局部编辑
R2 same_event_different_view   同一事件的不同视角/时刻
R3 same_entity_place_other_time 同一对象或地点、不同事件/时间
R4 visual_analogue_unrelated   视觉相似但实际无关
R5 unresolved                  无法可靠判断关系
```

R0/R1 常有助于恢复传播语境；R2 常有助于验证场景结构、对象关系和事件身份；R3 既能提供区分线索，也可能成为误关联陷阱；R4 用于测试 Agent 是否把相似性误当事实一致性。

即便命中完全相同图片，也不应仅凭像素匹配直接判真。更严谨的证据链是：

```text
RIS 命中
→ 访问承载页面
→ 验证页面时间、来源和具体陈述
→ 比较 query 与命中图是否存在裁剪/编辑
→ 判断该页面语境是否支持当前 claim
```

如果一个更早且可信来源明确给出与当前 claim 一致的时间、地点和事件，并且图片版本一致，它可以成为非常强的支持；如果它给出不同语境，则是强反证。搜索结果中的视觉相似本身只负责发现候选，不自动构成 verdict。

RIS 模块与端到端 Agent 可分别评估：

- `useful-visual-neighbor recall@k`：top-k 是否包含能区分当前候选的 R0–R3 结果；
- evidence-bearing page recall：相关图所在页面是否含可核验事实；
- false-bridge rate：是否把 R3/R4 错认成同一事件；
- reinspection yield：RIS 后返回检查正确图像区域的比例；
- decision gain：加入 RIS 相比禁用 RIS 的最终有据裁决增益；
- no-result calibration：无结果时是否保持未知，而不是推断为假或新图。

### 4.1 三种来源路线

#### 路线 A：复用公开 benchmark

可从 AVerImaTeC、VERITE、NewsCLIPpings、公开 OOC/多模态事实核查数据及其原始来源中筛选。AVerImaTeC 与本项目最接近：真实 image–text claims，并有网页 QA evidence。

优点：最快，已有标签或证据，便于和既有工作比较。
问题：任务可能以图文 claim 为输入而非纯单图；图片/网页会失效；公开答案可能被搜索到；许可通常适合研究引用或 URL 分发，不一定允许重新打包图片。

难度：中等。筛选和重审 100–200 例约需 10–25 人日。

#### 路线 B：从事实核查文章反向构建

从专业事实核查机构的 image-related claims 出发，恢复被核查图片、原始贴文、事实核查文章、首发/早期来源和独立证据。

优点：天然有真假争议和核查解释，真实传播分布较好。
问题：很多文章只嵌入截图或已删除社媒；事实核查文章本身可能泄漏答案；一个文章可能同时核查多个 claim；来源许可和图片保存方式复杂。

难度：高。论文级 gold 约 0.5–2.0 人日/case；100 例约 50–200 人日。

#### 路线 C：从许可图片/新闻事件正向构建

从 Wikimedia Commons、政府/公共机构媒体库、明确许可新闻图片或自有图片出发，构造正确语境和受控错误语境。

优点：许可、作者、时间和来源相对清楚，适合 frozen benchmark。
问题：容易只覆盖“干净世界”；错误 claim 往往是人工构造而不是真实谣言；若图片本身知名，RIS 会过于容易。

难度：中高。100–150 例约 30–90 人日。

### 4.2 真正昂贵的 gold 字段

每个真实 case 至少需要：

```text
query image / image URL / content hash
claim semantics 与 claim atoms
verdict + evidence sufficiency
原始或最早可确认的来源
支持、反驳和冲突的 exact webpage spans
source-family /转载关系
evidence cutoff 与抓取时间
冻结 SERP、网页正文、RIS observation
失效链接与工具失败记录
许可/分发方式
最小充分证据集
```

仅有图片和标签不足以评估 evidence-grounded Agent。

### 4.3 许可和分发

最稳妥的等级：

1. 自有或明确开放许可图片：可随数据发布；
2. 公共机构或研究条款允许的材料：保存许可与 attribution；
3. 新闻/社媒图片：优先发布 URL、hash、缩略/派生特征及重建脚本，不默认重新分发原图；
4. 已删除、私人或敏感内容：不纳入，或仅保留合规的审计元数据。

需要在立项时决定 benchmark 是公开分发、受控访问，还是只提供 evaluator service。这个选择会显著改变采集范围。

### 4.4 防止评测泄漏

若案例来自公开事实核查文章，Agent 可能直接搜索到标题和 verdict。应同时报告：

- frozen open-web：允许搜到事实核查文章，测现实任务成功率；
- source-masked：冻结环境中屏蔽直接给答案的 fact-check 页面，测证据调查；
- hidden rolling：近期新案例，在答案公开或进入主流索引前完成评测。

不能仅靠随机 image split。至少按事件、来源族、时间和近重复图片分组；若训练使用生成 world，还应保证真实 test 的事件/模板未出现在训练事实图中。

### 4.5 推荐真实评测规模

#### 第一轮工程评测

- 公开集适配：100–200 例；
- 自建许可清楚的真实图：30–50 例；
- 目标：验证任务 schema、抓取保存、RIS 记录和评分器。

粗估：15–40 人日。

#### 论文级静态真实测试

- 200–300 例；
- 三类各有足够样本，并覆盖 provenance、OOC、事实语义和 data void；
- 双人独立标注 + 仲裁；
- 冻结网页/SERP/RIS observation。

粗估：100–300 人日，具体取决于复用公开集比例和证据深度。

#### Hidden rolling test

- 每轮 30–60 个新案例；
- 每月或每季度刷新；
- 双人核验、冻结工具轨迹、跨后端复测。

粗估：每轮 20–60 人日；这是持续运营成本，不是一次性构建。

## 5. 相对难度与项目决策

| 问题 | 合成训练数据 | 真实评测数据 |
|---|---|---|
| 找到初始内容 | 较容易 | 中等 |
| 扩大图片数量 | 容易 | 困难 |
| 获得精确事实控制 | 可实现但验收难 | 通常无法干预 |
| 建立 region–claim 对齐 | 可自动生成再复核 | 人工成本高 |
| 来源/provenance 真实性 | 只有网页事实真实 | 必须逐例审计 |
| 反事实和 unverifiable 平衡 | 可控 | 很难自然收集 |
| 版权与重新分发 | 相对容易 | 可能成为硬阻塞 |
| 证明真实世界能力 | 不能单独证明 | 核心用途 |

因此资源分配不应按样本数平均。训练集追求规模、干预和过程监督；真实测试集追求少而精、完整 provenance 和严格隔离。

## 6. 推荐落地路线

### Gate 0：10-world spike（1–2 周）

- 10 个互联网事件；
- 每个 4 个合成视觉变体；
- 手工完成 evidence graph 和视觉验收；
- 验证是否至少有一半案例会真实触发“搜索后返回图片检查新区域”。

若做不到，问题多半是 claim 不可视觉化或网页事实不能指导重新观察，不应扩量。

### Gate 1：50-world MVP（4–8 周）

- 200 个合成 query cases；
- 50–100 条 blind rollout；
- 公开真实集适配 100 例；
- 自建真实测试 30–50 例；
- 完成 image-only/OCR-only/metadata-only 与 no-search leakage probes。

### Gate 2：论文级扩展

- 300–500 worlds，1,500–3,000 合成图；
- 200–300 例冻结真实测试；
- 30–60 例 hidden rolling test；
- 相同模型和预算下比较真实-only、普通合成、internet-grounded counterfactual 合成；
- 全部能力声明以真实测试结果为准，合成集只支撑机制和训练效率结论。

## 7. Go / No-Go 标准

进入大规模构建前，至少满足：

- 80% 以上通过验收的反事实对只改变一个决定性 claim atom；
- 简单 image-only/OCR-only/metadata-only 分类器不能远高于随机基线；
- Agent 在足够比例案例中会因搜索证据选择新的图像区域，而非只靠初始感知裁决；
- 至少 30 个真实案例的完整工具链和 gold 评分可以跑通；
- 真实测试数据的许可/分发策略得到明确确认；
- 合成训练在小规模真实测试上显示方向性收益，否则暂停 RL 和数据扩量。

## 8. 最终判断

该方案可做，但不属于“调用不限量生图 API 就能自动扩展”的低成本数据项目。合理的工程目标是让模型自动完成候选生成，让规则和多模型完成大部分筛选，把人工集中在 evidence correctness、反事实完整性和真实测试 gold 上。

如果资源有限，应优先保证：

1. 50 个高质量 world，而不是 5,000 张未经审计的图片；
2. 100 个高质量真实测试案例，而不是 1,000 个只有标签、没有证据图的真实图片；
3. 可证明合成数据带来真实迁移收益的消融，而不是单独报告合成环境高分。
